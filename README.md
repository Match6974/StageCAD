# StageCAD

舞台業務向け2D CADの試作版です。開発順序は `docs/specs/roadmap.csv`、機能仕様は `docs/specs/feature.csv`、開発ルールは `AGENTS.md` を参照してください。

## STEP 1：mm単位の座標管理と縮尺設定

対応する機能IDは `180100`・`180200`（座標と用紙の基盤）、`291100`・`330200`・`330401`（縮尺設定）です。図形描画やレイヤー追加は後続STEPで実装します。

### 操作

1. 起動時にPDFを選択すると、従来のPDFビューアを「PDF参照」タブに表示します。選択をキャンセルしてもアプリは起動します。
2. 「作業領域」タブを選択します。A4用紙の中心の十字が原点です。カーソル位置の実寸座標を下部にmmで表示します。Xは右向き、Yは上向きが正です。
3. ツールバーの「縮尺…」を押し、1:1・1:10・1:100、または「任意の縮尺」を選択します。1:50なら分母欄に `50` を入力します。
4. 「OK」で適用します。「キャンセル」やEscでは変更しません。初期値は1:1です。

縮尺の分母は描画精度を保てる範囲として0.000001〜10000、入力は小数点以下12桁までです。小数点記号はOSのロケールに従い、桁区切りや指数表記は使用しません。不正な入力ではOKを押せません。

縮尺変更は用紙上の換算を変えます。実寸1000mmの線は1:100で紙面上10mm、1:50で20mmとなり、内部座標や実寸は1000mmのままです。作業領域は画面サイズに合わせて自動フィットします。この表示倍率と縮尺は独立しています。

用紙は現在A4固定です。破線はCSVの参考値である201.4×287.9mmの印刷領域を表し、実際のプリンターから取得した印刷可能範囲ではありません。用紙と印刷領域は同じ原点を中心に配置します。

### 今回の範囲

- `DrawingSettings` が、単一作業領域の縮尺と実寸mmから用紙mmへの変換を保持します。将来のレイヤーごとに独立したインスタンスを持てる構造です。
- `DrawingView` のシーン座標は実寸mmです。画面ピクセルへの変換でY方向を反転し、縮尺・画面表示倍率を適用します。縮尺の変更では図形の座標を書き換えません。
- PDF参照タブは従来の独立した表示です。作業領域の縮尺は適用しません。PDFの作業領域への配置・既知距離による補正は、次の「PDFを縮尺に合わせる機能」で扱います。
- 設定の保存、レイヤー追加・切り替え、図形描画・編集、PDF出力は未実装です。縮尺は現在のウィンドウのメモリ上だけに保持します。

## ビルド・テスト

開発環境はAGENTS.md指定のQt 6.11.1、CMake、C++コンパイラーを使用してください。Qt Creatorでは対象のQtキットを選択します。既存CMakeの最低要求Qtバージョン6.5は維持しています。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure
```

テストにはQt Testが必要です。`-DBUILD_TESTING=OFF` でアプリだけをビルドできます。アプリの起動ファイルはNinja等では `build/PDFOpen`、Visual StudioのDebug構成では `build/Debug/PDFOpen.exe` です。

準備済みCodexクラウド環境では、各シェルで `. /workspace/.stagecad-setup/env.sh` を実行すると開発ツールを使用できます。この環境での実行検証はLinux・Qt 6.8.2であり、Qt 6.11.1・Windows/MSVC・macOSでの検証は別途必要です。

自動テストはオフスクリーンで、定型・任意縮尺の数値換算、原点・軸方向、縮尺や表示倍率を変更しても図形座標が変わらないこと、不正入力、ダイアログの適用・キャンセル、ロケール別小数入力、既存PDFの選択・描画を検証します。
