# StageCAD

舞台業務向け2D CADの試作版です。開発順序は `docs/specs/roadmap.csv`、機能仕様は `docs/specs/feature.csv`、開発ルールは `AGENTS.md` を参照してください。

## STEP 1：mm単位の座標管理と縮尺設定

対応する機能IDは `180100`・`180200`（座標と用紙の基盤）、`291100`・`330200`・`330401`（縮尺設定）です。図形描画やレイヤー追加は後続STEPで実装します。

### 操作

1. 起動時にPDFを選択すると、従来のPDFビューアを「PDF参照」タブに表示します。選択をキャンセルしてもアプリは起動します。
2. 「作業領域」タブを選択します。A4用紙の中心の十字が原点です。カーソル位置の実寸座標を下部にmmで表示します。Xは右向き、Yは上向きが正です。
3. ツールバーの「縮尺…」を押し、1:1・1:10・1:100、または「任意の縮尺」を選択します。1:50なら分母欄に `50` を入力します。
4. 「OK」で適用します。「キャンセル」やEscでは変更しません。初期値は1:1です。

縮尺の分母は描画精度を保てる範囲として0.000001〜10000、入力は小数点以下12桁までです。小数点記号はOSのロケールに従い、桁区切りや指数表記は使用しません。不正な入力ではOKを押せません。

縮尺変更は用紙上の換算を変えます。実寸1000mmの線は1:100で紙面上10mm、1:50で20mmとなり、内部座標や実寸は1000mmのままです。作業領域は画面サイズに合わせて自動フィットします。この表示倍率と縮尺は独立しています。

用紙は現在A4固定です。破線はCSVの参考値である201.4×287.9mmの印刷領域を表し、実際のプリンターから取得した印刷可能範囲ではありません。用紙と印刷領域は同じ原点を中心に配置します。

### 今回の範囲

- `DrawingSettings` が、単一作業領域の縮尺と実寸mmから用紙mmへの変換を保持します。将来のレイヤーごとに独立したインスタンスを持てる構造です。
- `DrawingView` のシーン座標は実寸mmです。画面ピクセルへの変換でY方向を反転し、縮尺・画面表示倍率を適用します。縮尺の変更では図形の座標を書き換えません。
- PDF参照タブは元のPDFの独立した表示です。作業領域の縮尺や、作業領域で行ったPDFの伸縮は適用しません。
- 設定の保存、レイヤー追加・切り替え、図形描画・編集、PDF出力は未実装です。縮尺は現在のウィンドウのメモリ上だけに保持します。

## STEP 1：PDFを縮尺に合わせる機能

関連する機能IDは `19020702`（PDF取り込み）、`190519`（伸縮ダイアログ）、`360201`〜`360204`（現在の距離・新しい距離とそれぞれの測定ボタン）、`360700`・`360800`（キャンセル・OK）です。今回は縦横比を保つ距離補正を実装しています。

### 操作

1. 「作業領域」で縮尺を設定し、「PDF取り込み…」からPDFを選択します。起動時に選択したPDFも作業領域へ取り込み済みです。複数ページのPDFはツールバーの「ページ」で対象ページを切り替えられます。
2. 「PDFの伸縮…」→現在の距離の「2点から測定」を押します。一時的にダイアログが隠れるので、PDF内の始点・終点を順にクリックします。**この1点目のCAD座標を固定**します。同じ点を2回クリックした場合は終点を指定し直します。
3. ダイアログに戻ったら「新しい距離」に正しい実寸を入力します。単位はmmまたはcmです。例えば測定値が100mm、本来の長さが5000mmなら、5000mmを入力します。現在の距離も測定後に数値修正できますが、固定点は測定した1点目のままです。
4. 新しい距離も「2点から取得」で作業領域上の別の2点から取得できます。こちらの測定では固定点を変更しません。
5. 「OK」で `新しい距離 ÷ 現在の距離` の倍率をPDF全体に適用します。縦横比と1点目の位置を維持し、対象ページの実寸サイズだけを補正します。他の図形や作業領域の縮尺、元のPDFファイルは変更しません。

測定中のEscはその測定を中止し、ダイアログに戻ります。ダイアログのキャンセル・Esc・閉じる操作では補正を適用しません。現在の距離の1点目が未指定、距離が0・負数・非数値の場合はOKを押せません。距離の上限は10000000mmです。補正後のPDFの幅・高さは0.000001〜10000000mm、各端の座標は±10000000mm以内に制限しています。範囲外の補正はエラーとなり、元の配置を維持します。

点を細かく指定したい場合は「拡大」「縮小」とスクロールバーを使用します。「用紙全体」で基準の表示倍率に戻ります。これらは画面表示だけの変更で、計測値やPDFの実寸を変えません。

### 初期配置と状態の保持

- 取り込み時はPDFページの物理寸法（1ポイント＝1/72インチ）に、その時点の作業領域の縮尺の分母を掛けた実寸サイズで、中心を原点に配置します。例えば1:100の図面なら、先に作業領域の縮尺を1:100に設定して取り込むと、紙面と同じ大きさで表示される初期状態から補正できます。
- **取り込み後の縮尺変更はPDFの実寸を変更しません。** 既知距離による補正と、図面の表示・用紙への換算は別の処理です。
- 現在の1つのPDFについて、ページごとの補正結果をメモリ上に保持します。ページを切り替えて戻っても補正結果を復元します。まだ表示していないページの初期サイズにも、取り込み時点の縮尺を使用します。
- 別のPDFの取り込みや同じPDFの取り込み直しでは、現在のPDFと各ページの補正状態を置き換えます。ファイル選択のキャンセルや読み込み失敗では、現在のPDFと補正状態を維持します。
- ページの描画画像は長辺最大2400pxです。大きく拡大すると画像がぼやける場合がありますが、距離の計算は画像ピクセル数ではなくCADの実寸mm座標で行います。クリック位置の精度は画面表示倍率に依存します。
- パスワード付きPDF、複数PDFの同時配置、補正状態の保存・読み込み、補正したPDFの出力は未対応です。アプリを終了すると補正状態は失われます。

## ビルド・テスト

開発環境はAGENTS.md指定のQt 6.11.1、CMake、C++コンパイラーを使用してください。Qt Creatorでは対象のQtキットを選択します。既存CMakeの最低要求Qtバージョン6.5は維持しています。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure
```

テストにはQt Testが必要です。`-DBUILD_TESTING=OFF` でアプリだけをビルドできます。アプリの起動ファイルはNinja等では `build/PDFOpen`、Visual StudioのDebug構成では `build/Debug/PDFOpen.exe` です。

準備済みCodexクラウド環境では、各シェルで `. /workspace/.stagecad-setup/env.sh` を実行すると開発ツールを使用できます。この環境での実行検証はLinux・Qt 6.8.2であり、Qt 6.11.1・Windows/MSVC・macOSでの検証は別途必要です。

自動テストはオフスクリーンで、定型・任意縮尺の数値換算、原点・軸方向、縮尺や表示倍率を変更しても図形座標が変わらないこと、不正入力、ダイアログの適用・キャンセル、ロケール別小数入力、既存PDFの選択・描画を検証します。

PDF補正のテストでは、1点目の固定、補正後の距離と縦横比、上下反転しない描画、mm/cm換算、測定中のEsc、無効な距離や過大な補正で状態が変わらないこと、ファイル選択・補正のキャンセル、ページ別補正の復元、縮尺変更による実寸不変を検証します。

終了テストは、実際のイベントループを実行してからスタック上のMainWindowを破棄します。PDF未読込、読込済み、補正済み、伸縮ダイアログ表示中、2点測定中、ダイアログのキャンセル直後の6状態を検証します。

### Windowsで終了時にスタック破損のエラーが出る場合

`Run-Time Check Failure #2 - Stack around the variable 'w' was corrupted` は、MainWindowのサイズが変わった後に古いオブジェクトファイルが混在した場合にも発生します。このメッセージだけでは原因は確定できません。まず、空の新しいビルドディレクトリで全ソースをビルドして切り分けます。

1. アプリを終了し、Qt Creatorの「プロジェクト」→「ビルド設定」を開きます。
2. ビルドディレクトリを、未使用のフォルダー（例：`D:/D/Qt/StageCAD/build-step1-clean`）に変更します。ソースフォルダーはそのままにします。
3. 「CMake の実行」→Ctrl+Bで構成・ビルドします。
4. 実行対象を `PDFOpen` にしてCtrl+Rで実行し、ウィンドウの×で終了します。

新規ビルドでも再現する場合は、終了直前の状態と、デバッガーで停止したときのコールスタックを確認します。クラウドのLinuxでの検証結果だけではWindows固有の問題の解消を保証できません。
